# 🏥 نظام الإنذار المبكر لتفشي الكوليرا في اليمن
## Cholera Early Warning System in Yemen

مشروع بحثي تطبيقي يدرس استخدام معالجة البيانات وتعلّم الآلة لتحليل مؤشرات الكوليرا والعوامل البيئية والإنسانية المرتبطة بها في اليمن، مع واجهة تفاعلية مبنية باستخدام Streamlit.

> **تنبيه:** هذا المشروع أداة تحليلية/بحثية مساعدة، وليس نظامًا طبيًا معتمدًا أو بديلًا عن الترصد الوبائي والقرارات الصادرة عن الجهات الصحية. لا تُستخدم التنبؤات أو عتبات الإنذار لاتخاذ قرارات ميدانية قبل التحقق من الأداء والبيانات ومراجعتها من مختصين.

## 🎯 نبذة عن المشروع

يهدف المشروع إلى تنظيم وتحليل البيانات الوبائية والبيئية والإنسانية المتعلقة باليمن، ودراسة إمكانية الاستفادة من تعلّم الآلة في استكشاف الأنماط الزمنية والتنبؤ بمؤشرات حالات الكوليرا. ويُعرض الناتج من خلال تطبيق تفاعلي مبني باستخدام Streamlit.

## 🎯 الأهداف

- تحليل بيانات الكوليرا التاريخية وتجهيزها للتحليل.
- الاستفادة من بيانات الأمطار والمناخ والنزوح والبنية التحتية والمياه والصرف الصحي عند توافرها وملاءمتها.
- إنشاء ميزات زمنية تساعد على تدريب نموذج تنبؤي.
- تدريب نموذج تعلّم آلة وتقييمه باستخدام تقسيم زمني مناسب.
- عرض المؤشرات والتنبؤات في واجهة تفاعلية.
- دعم التحليل والتخطيط، دون اعتبار النموذج بديلًا عن التقييم الوبائي المتخصص.

## 📂 مصادر البيانات

يحتوي مجلد `data/` على البيانات الخام التي يعتمد عليها خط المعالجة. **يجب الحفاظ على الملفات الأصلية دون تعديل مباشر**؛ وتُجرى عمليات التنظيف والتحويل على نسخ أو بيانات مشتقة منها.

تتضمن البيانات المذكورة في هيكل المشروع:

- بيانات وبائية عن تفشي الكوليرا على مستوى اليمن.
- بيانات الأمطار والنزوح الداخلي.
- بيانات التغير المناخي.
- بيانات الحوادث والمعلومات الإنسانية.
- بيانات الأنشطة والمساعدات.
- بيانات البنية التحتية والقطاع العام.
- مؤشرات المياه والصرف الصحي والنظافة (WASH).
- ملفات البيانات الوصفية الخاصة ببيانات الكوليرا على المستوى الوطني ومستوى المحافظات.
- ملف بيانات الحوادث المرتبطة بالنزاع بصيغة Excel.
- أربعة ملفات من بيانات NASA POWER.

تختلف تغطية كل مصدر ودقته الزمنية والجغرافية؛ لذلك ينبغي التحقق من تعريف الأعمدة والفترات الزمنية والوحدات قبل دمج البيانات. وجود ملف ضمن مجلد البيانات لا يعني بالضرورة أنه مستخدم حاليًا في النموذج.

## 🔬 منهجية العمل

يتكون سير العمل العام من المراحل التالية، وفقًا لطبيعة الملفات والوظائف المنفذة في `code/data_pipeline.ipynb` و`code/app.py`:

1. **استكشاف البيانات:** فحص الأعمدة وأنواع البيانات والفترات الزمنية والقيم المفقودة.
2. **تنظيف البيانات:** معالجة التواريخ والتكرارات والقيم غير الصالحة، مع الحفاظ على الملفات الخام.
3. **توحيد الدقة الزمنية:** مواءمة البيانات الوبائية والمناخية والإنسانية ضمن فترات قابلة للمقارنة.
4. **دمج المصادر:** إنشاء جدول تحليلي موحد عندما تسمح مفاتيح الربط والفترات الزمنية بذلك.
5. **هندسة الميزات:** إنشاء متغيرات مشتقة من البيانات السابقة والعوامل الزمنية، وفقًا لما ينفذه خط المعالجة.
6. **تدريب النموذج وتقييمه:** تدريب نموذج تعلّم آلة وتقييم أدائه على بيانات لم تُستخدم في التدريب.
7. **عرض النتائج:** استخدام تطبيق Streamlit لعرض المعلومات المتاحة في النموذج.

### مبدأ مهم عند التقييم

لأن البيانات زمنية، ينبغي الحفاظ على الترتيب الزمني عند تقسيم التدريب والاختبار، وتجنب تسرب معلومات المستقبل إلى بيانات التدريب أو الميزات. كما ينبغي مقارنة النموذج بخط أساس بسيط والإبلاغ عن مقاييس الأداء المحسوبة فعليًا.

## ⚙️ متطلبات التشغيل

- Python 3.8 أو أحدث، إذا كان متوافقًا مع المكتبات المستخدمة في الكود.
- المكتبات المحددة في `requirements.txt`.
- ملفات البيانات الخام داخل `data/`.
- تشغيل خط المعالجة والتدريب قبل تشغيل الواجهة إذا كانت الواجهة تعتمد على ملفات نموذج مولدة.

### ملف المكتبات `requirements.txt`

يجب أن يحتوي `requirements.txt` على المكتبات التي يستوردها الكود فعلًا. قد تشمل المكتبات الشائعة في هذا النوع من المشاريع:

```text
pandas
numpy
scikit-learn
xgboost
streamlit
plotly
joblib
matplotlib
seaborn
openpyxl
```

هذه قائمة إرشادية وليست تأكيدًا على متطلبات المشروع النهائية. راجع الاستيرادات داخل `code/app.py` ودفتر `code/data_pipeline.ipynb`، وثبّت إصدارات متوافقة في ملف المتطلبات الفعلي.

## 🚀 تثبيت المشروع وتشغيله

نفّذ الأوامر التالية من المجلد الرئيسي `cholera_in_yemen/`.

### 1. التحقق من Python

```bash
python --version
```

### 2. إنشاء بيئة افتراضية (موصى به)

على Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
```

على Linux أو macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. تثبيت المكتبات

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. تشغيل واجهة Streamlit

بما أن ملف الواجهة موجود في مجلد `code/`، شغّله من المجلد الرئيسي بالأمر:

```bash
streamlit run code/app.py
```

بعد بدء التشغيل، سيعرض Streamlit عنوان التطبيق المحلي في الطرفية، وغالبًا يكون:

`http://localhost:8501`

### 5. تشغيل خط المعالجة

ملف خط المعالجة هو دفتر Jupyter Notebook:

`code/data_pipeline.ipynb`

افتحه باستخدام Jupyter Notebook أو JupyterLab، ثم نفّذ الخلايا بالترتيب وفقًا للتعليمات داخل الدفتر. إذا كان الدفتر يحتاج إلى مسارات نسبية، فالأفضل تشغيل Jupyter من المجلد الرئيسي للمشروع، والتحقق من أن المسارات تشير إلى `data/` و`outputs/` كما هو متوقع.

> لا يمكن تأكيد ترتيب التنفيذ الدقيق أو أسماء الخلايا أو جميع المخرجات دون مراجعة محتوى الدفتر نفسه. اتبع تعليماته وتحقق من رسائل التنفيذ قبل تشغيل الواجهة.

## 📦 المخرجات

بحسب مخطط المشروع، يُتوقع أن يحتوي مجلد `outputs/` على العناصر التالية بعد تشغيل مراحل المعالجة والتدريب، إذا كان الكود ينشئها بهذه الأسماء:

| الملف | الغرض الموضح في المخطط |
|---|---|
| `cholera_weekly_cleaned.csv` | بيانات الكوليرا بعد التنظيف والتجميع الأسبوعي |
| `rainfall_national_weekly.csv` | بيانات الأمطار المجمعة أسبوعيًا على المستوى الوطني |
| `idps_national.csv` | بيانات النازحين المجمعة على المستوى الوطني |
| `merged_data_final.csv` | مجموعة البيانات المدمجة |
| `final_features.csv` | البيانات بعد تجهيز الميزات |
| `cholera_model.pkl` | النموذج المدرّب |
| `features_list.pkl` | قائمة الميزات المستخدمة في النموذج |

هذه الأسماء والأوصاف مستندة إلى المخطط المقدم، ويجب مطابقتها مع ما ينتجه الكود فعليًا. لا ترفع ملفات المخرجات أو النماذج إلى GitHub إلا بعد التأكد من ملاءمتها وحجمها وعدم احتوائها على معلومات لا ينبغي نشرها.

## ⚠️ ملاحظات مهمة

- **البيانات الخام:** لا تعدّل الملفات الأصلية داخل `data/` مباشرة. احتفظ بنسخة أصلية قابلة لإعادة الاستخدام.
- **المسارات:** اجعل المسارات في الأكواد واضحة ومتوافقة مع بنية `cholera_in_yemen/`، وتجنب الاعتماد على مجلد العمل الحالي دون التحقق منه.
- **البيانات المكانية والزمنية:** لا تدمج المصادر اعتمادًا على أسماء الأعمدة فقط؛ تحقّق من معنى كل متغير ووحدته وتاريخه ومستواه الجغرافي.
- **النتائج العلمية:** لا تذكر أرقام أداء للنموذج قبل حسابها على مجموعة اختبار مناسبة وتوثيقها.
- **الإنذارات الصحية:** يجب اعتماد أي عتبات أو توصيات تشغيلية بالتشاور مع خبراء الصحة العامة والجهات المختصة.
- **البيانات والحقوق:** راجع تراخيص وشروط استخدام كل مصدر بيانات قبل إعادة نشر الملفات الخام ضمن المستودع.
- **الملفات المولدة:** يمكن استخدام `.gitignore` لاستثناء البيئة الافتراضية والملفات المؤقتة، مع اتخاذ قرار واعٍ بشأن ملفات النموذج والمخرجات.
